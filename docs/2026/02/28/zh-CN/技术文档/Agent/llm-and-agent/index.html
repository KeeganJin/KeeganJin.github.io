LLM 与 Agent 的关系

LLM：Agent 的”大脑”

大语言模型（LLM）在 Agent 系统中扮演着”大脑”的角色。它负责理解输入、推理决策、生成输出——这些是 Agent 智能行为的核心来源。

LLM 在 Agent 中的角色

LLM 在 Agent 系统中承担多个关键职能：

1. 语言理解

LLM 的首要任务是理解用户的自然语言输入：

  • 意图识别：理解用户想要做什么
  • 任务解析：将模糊需求转化为明确任务
  • 上下文理解：基于历史对话理解当前请求
  • 歧义消解：处理不明确或多种解释的输入

2. 推理与规划

LLM 的推理能力是 Agent 决策的核心：

  • 任务分解：将复杂任务拆解为子任务
  • 步骤规划：确定完成任务所需的步骤顺序
  • 条件推理：根据条件选择不同的行动路径
  • 因果推理：预测行动的可能后果

3. 决策生成

LLM 根据推理结果生成具体决策：

  • 工具选择：决定调用哪些工具
  • 参数生成：生成工具调用的参数
  • 策略调整：根据执行反馈调整策略
  • 失败处理：处理执行失败的情况

4. 内容生成

LLM 生成 Agent 的输出内容：

  • 回答生成：生成对用户的回复
  • 报告撰写：生成分析报告、总结等
  • 代码生成：生成代码片段或完整程序
  • 解释说明：解释决策过程和结果

LLM 的能力边界

尽管 LLM 能力强大，但它也存在明确的局限。理解这些局限是设计 Agent 系统的关键。

LLM 能做什么

能力 描述
自然语言理解 高质量地理解文本语义、意图、上下文
知识问答 利用训练知识回答各类问题
内容生成 生成文本、代码、创意内容
推理能力 进行一定程度的逻辑推理和任务规划
多语言处理 处理多种语言的输入和输出
格式遵循 按指定格式生成输出（JSON、表格等）

LLM 不能做什么

局限 描述
实时信息获取 无法获取训练后的新信息
数学精确计算 复杂数学计算可能出错
长期状态维护 无法自身维护长期记忆
物理世界交互 无法直接操作物理世界
事实性保证 可能生成不真实的内容
无限上下文 上下文窗口有限
确定性执行 相同输入可能产生不同输出

从 Chatbot 到 Agent 的演进

Chatbot 的局限

传统的 Chatbot 系统存在明显局限：

  1. 单轮问答：每次输入独立处理，缺乏行动连续性
  2. 被动响应：只能回答问题，不能主动解决问题
  3. 无工具能力：无法获取实时信息或执行操作
  4. 短记忆：对话上下文有限，无法长期记忆

Agent 的突破

Agent 通过以下机制突破了 Chatbot 的局限：

1. 工具调用（Tool Use）

Agent 可以调用外部工具来扩展能力：

  • 搜索引擎：获取实时信息
  • 代码执行：进行精确计算
  • API 调用：与外部系统交互
  • 文件操作：持久化存储信息

2. 记忆系统（Memory）

Agent 维护多层记忆：

  • 短期记忆：当前对话上下文
  • 工作记忆：当前任务状态
  • 期记忆：跨会话的知识和经验

3. 规划能力（Planning）

Agent 可以规划多步骤行动：

  • 任务分解：复杂任务拆解为简单子任务
  • 步骤排序：确定行动顺序
  • 反馈调整：根据结果调整计划

4. 自主行动（Autonomy）

Agent 可以自主决策和行动：

  • 自主选择工具
  • 自主调整策略
  • 自主判断完成状态

LLM Agent 的典型架构

基本架构

详细架构

一个完整的 LLM Agent 通常包含以下模块：

输入处理模块

  • 接收用户输入
  • 解析意图和任务
  • 加载相关上下文和记忆

LLM 核心模块

  • 处理输入并生成决策
  • 进行推理和规划
  • 生成工具调用指令或输出内容

工具模块

  • 注册可用工具
  • 执行工具调用
  • 返回执行结果

记忆模块

  • 存储对话历史
  • 存储任务状态
  • 存储长期知识

输出模块

  • 格式化输出内容
  • 向用户展示结果
  • 记录交互日志

为何需要 Agent：LLM 单独无法完成的事情

1. 实时信息获取

LLM 的知识来源于训练数据，无法获取训练后发生的事情。Agent 通过搜索工具可以获取实时信息。

示例：

  • 用户：”今天北京的天气怎么样？”
  • Chatbot：”抱歉，我无法获取实时天气信息。”
  • Agent：调用天气 API → 返回实时天气数据

2. 精确计算

LLM 在复杂数学计算上容易出错。Agent 可以调用代码执行工具进行精确计算。

示例：

  • 用户：”计算 123456789 × 987654321”
  • Chatbot：可能给出错误结果
  • Agent：执行 Python 计算 → 返回精确结果

3. 多步骤任务

复杂任务需要多个步骤，LLM 单次输出难以完成。Agent 可以迭代执行多个步骤。

示例：

  • 用户：”帮我分析这份销售数据并写一份报告”
  • Chatbot：”请提供具体数据…”
  • Agent：
    1. 调用工具读取数据文件
    2. 执行数据分析代码
    3. 生成可视化图表
    4. 撰写分析报告

4. 外部系统交互

LLM 无法直接操作外部系统。Agent 可以通过 API 与各种系统交互。

示例：

  • 用户：”把会议安排到明天下午 3 点”
  • Chatbot：”我无法操作您的日历。”
  • Agent：调用日历 API → 创建会议 → 确认完成

5. 长期任务跟踪

跨会话的任务需要长期记忆。Agent 可以持久化存储任务状态。

示例：

  • 第一天：”帮我监控这个股票的价格变化”
  • Agent：记录任务 → 开始监控
  • 第二天：”股票价格怎么样了？”
  • Agent：从记忆加载任务 → 返回监控结果

LLM 选择考量

选择合适的 LLM 作为 Agent “大脑”时，需要考虑：

能力要求

  • 推理能力：复杂任务规划需要强推理
  • 工具调用：需要支持 Function Calling
  • 长上下文：长任务需要长上下文窗口
  • 输出格式：需要稳定遵循输出格式

成本考量

  • 调用成本：API 调用费用 vs 自托管成本
  • 延迟要求：实时响应 vs 批量处理
  • 并发需求：单用户 vs 多用户服务

可选方案

LLM 特点 适用场景
GPT-4/GPT-4o 强推理、Function Calling 复杂任务、企业应用
Claude 强推理、长上下文、安全 复杂分析、长文档处理
LLaMA 开源、可自托管 成本敏感、隐私要求高
Gemini 多模态、长上下文 图像+文本任务

总结

LLM 是 Agent 的核心组件，提供理解、推理、决策、生成能力。但 LLM 有明确的局限：无法获取实时信息、无法精确计算、无法维护长期状态、无法直接与外部系统交互。Agent 通过添加工具调用、记忆系统、规划机制，扩展了 LLM 的能力边界，使其能够完成更复杂的任务。

选择合适的 LLM 作为 Agent “大脑”，需要平衡能力、成本、延迟等多方面因素。
